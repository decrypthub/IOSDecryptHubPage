从注入到证据

面向公开版本的使用与能力参考：选择注入方式，连接设备端面板，再用 idh / MCP 读取运行时事实。

开始前

IOSDecryptHub 运行在目标 App 进程内。它记录调用发生时的参数、结果和调用栈，不是代理服务器，也不会替你获得目标 App 的授权。

  1. 确认分析范围

    只对自有 App 或已获授权的测试目标操作，并准备一台支持 TrollStore 或越狱注入的设备。

  2. 选择注入路线

    TrollStore 路线使用 dylib 或管理器 App；越狱路线使用插件源中的 rootless / roothide 包。

  3. 启动并连接面板

    启动目标 App 后，在可信局域网的浏览器中打开设备端显示的地址，默认端口从 8088 开始。

  4. 决定是否接入 idh

    只看面板可以停在这里；需要命令行、事件导出或 AI 客户端时，再安装 PC 端 idh 网关。

公开版本不做设备自动发现：请使用设备端显示的 IP 和端口手动连接。

安装与连接

三条注入路径共享同一份核心引擎。差别只在于谁负责把 dylib 放进目标 App 进程。

01 · TROLLSTORE

TrollStore 注入器（推荐）

适用于已经安装 TrollStore 和兼容注入器的设备：

  1. 从首页或 GitHub Releases 下载当前版本 dylib。
  2. 在注入器中选择授权目标 App，添加 dylib 并执行注入。
  3. 完全退出并重新启动目标 App。
  4. 从悬浮窗或日志输出确认面板地址，再用浏览器打开。
02 · JAILBREAK

越狱插件源

适用于 rootless / roothide 环境。两种包对应不同的设备架构，不能混装：

  1. 在 Sileo、Zebra 等包管理器中添加插件源。
  2. 安装 com.iosdecrypthub，选择与设备环境匹配的包。
  3. 在“设置 → IOSDecryptHub”中选择授权目标 App。
  4. 重启目标 App，并使用设备端显示的地址连接。
https://ios.decrypthub.com/

PC 端 · idh 网关

idh 不负责发现设备。先从设备面板、悬浮窗或诊断信息取得 IP 和实际端口，再保存连接：

python3 -m pip install ios-decrypt-hub
idh connect <device-ip>:<port>
idh devices
idh mcp

idh mcp 将设备端 Streamable HTTP MCP 桥接为本机 stdio MCP，可配置给 Codex、Claude 等 AI 客户端。只有一个在线目标时可以省略 target_id。

分析流程

建议先观察，再缩小范围，最后导出证据。这样可以把高频系统噪声与真正的业务调用分开。

01

先看事件流

在面板中按分类、关键词和输入大小筛选加解密、文件、网络与 Keychain 事件。

02

回到调用点

打开单条事件查看输入输出、算法元数据和应用层调用栈，再用 symbolicate 或反汇编确认上下文。

03

关联因果链

以网络请求的构建时刻为锚点，关联同一时间窗内的摘要、签名、加密和 Keychain 操作。

04

保存最小证据

只导出完成问题所需的事件和诊断信息，敏感字段应在本地加密保存，不要直接分享原始日志。

MCP 工具

设备端 MCP 复用 HTTP 服务端口 POST /api/mcp，当前公开版本提供 44 个工具，覆盖反汇编、镜像与符号、运行时事件、沙盒文件、脱壳、动态观察和配置。

先调用 get_capabilities 和 tools/list 获取当前构建的真实能力。工具可能受变体、目标镜像和设备环境影响，网页示例不是运行时结果。

    边界与限制
    
              
    运行时观察能力有明确边界。把“没有看到”当成线索，而不是把它当成“绝对不存在”。
    
              
      
                
    • Hook 只覆盖实际可改写的导入符号和 Objective-C 方法；静态链接、私有调用路径或未触发的 API 可能不会出现事件。
      • 
                
    • 脱壳只处理当前进程已加载的 App Bundle Mach-O；PlugIns/*.appex 等独立进程需要单独注入。
      • 
                
    • MCP 的内存读取和 xref 扫描有大小、可读页和分页限制；响应中的 coverage / confidence 字段必须一并判断。
      • 
                
    • 网络层是进程内 best-effort 观察：系统 TLS、未走 NSURLSession 的实现或 App 自带库可能需要不同的观察面。
      • 
              
    
            
    

            
    
              
    安全使用
    
              
      
                
    • Web 与 MCP 服务默认从 8088 开始监听，服务没有身份认证，并可能在端口占用时选择 8088-8108 的空闲端口；仅限可信网络使用，绝不要暴露到公网。
      • 
                
    • 事件、导出文件和 MCP 响应可能包含 Key、IV、明文、Token、路径及请求内容，请按敏感材料保存和传输。
      • 
                
    • 仅分析自有 App 或已获授权目标。注入、重签和脱壳能力会受到设备环境、签名和目标 App 保护机制影响。
      • 
                
    • 提交 Issue 或公开复现步骤前，先删除凭据、用户数据、设备标识和完整原始日志。
      • 
              
    
              
    遇到问题可在 GitHub Issues 反馈，并附上脱敏后的版本、设备环境和诊断摘要。
